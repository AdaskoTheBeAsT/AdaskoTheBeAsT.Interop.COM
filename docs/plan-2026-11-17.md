# Library Improvement Plan — Phase 2: Direct Factory Isolation, `IErrorInfo`, Bidirectional ProgIDs, STA Pre-Warming & Automation Locale Guards (2026-11-17)

## Scope and guardrails

This follow-up plan captures the remaining general-purpose COM interop capabilities identified across multi-worker STA COM host workloads after completing `COM-01`–`COM-08` (`docs/plan-2026-11-14.md`) and cross-checking against the sibling `AdaskoTheBeAsT.Interop*` repositories:

- **Prepared:** 2026-11-17
- **Repository:** `AdaskoTheBeAsT.Interop.COM`
- **Baseline:** Uncommitted `v5.0.0` workspace (`net11.0;net10.0;net481;net48;net472`, `.NET SDK 11.0.100`, C# 14, `COM-01`–`COM-08` implemented and passing `1,078/1,078` tests on both `x86` and `x64`).
- **Target release:** Fold into the open `v5.0.0` major version prior to tagging/publishing.
- **Core constraints:**
  - Zero external runtime NuGet package dependencies across all five retained TFMs (`net11.0`, `net10.0`, `net481`, `net48`, `net472`).
  - Keep `IComExecutor` unchanged (five original members). Keep all existing default behaviors non-surprising; registry writes, WinSxS bypass, and per-module quirk shims remain explicit opt-ins.
  - Strict Write-Xor-Execute (W^X) memory hygiene (`PAGE_READWRITE` with original protection restoration; never simultaneous write+execute pages).
  - Strict thread-affinity validation on all disposable scopes (`ComAutomationLocaleScope`, `IComActivationScope`, `ComObjectHandle<T>`).
  - Validate every work item with real native C++ fixtures in `NativeLifetimeProbe.dll` across both `x86` (`Win32`) and `x64` on all five retained TFMs with `TreatWarningsAsErrors=true`.

## Executive summary

Even with `COM-01`–`COM-08` in place, nine recurring **pure-COM** patterns still required custom boilerplate in multi-worker COM hosts:

1. **No explicit WinSxS bypass on Desktop Windows (`ForceInProcessFallback`):** Applications hosting `Microsoft.Jet.OLEDB.4.0` / OLE DB service components or isolating worker-cloned DLLs sharing identical `<assemblyIdentity>` tuples cannot always use Win32 `CreateActCtxW` on Desktop Windows because Win32 SxS `HKCR\CLSID` virtualization hides `OLEDB_SERVICES = 0xfffffffe` and provider subkeys from `oledb32.dll` (`MSDAINITIALIZE`), and SxS caches assembly identities across threads.
2. **Process-lock serialization around `new MyComClass()` across isolated worker copies:** Multi-worker hosts often wrap COM object creation in a static `Lock` when concurrent workers load private copies of the same COM DLL sharing identical CLSIDs. Direct `DllGetClassObject` + `IClassFactory::CreateInstance` against a worker's `HMODULE` eliminates global `CoRegisterClassObject` CLSID table contention and prevents accidental fallback to global `HKLM` registrations.
3. **Lost VB6 / ATL / Delphi / ADO `IErrorInfo` diagnostics & VB6/ActiveX `HRESULT` decoding:** Native COM servers populate thread-local `oleaut32!GetErrorInfo` (`Source`, `Description`, `GUID`, `HelpFile`, `HelpContext`), whereas managed `COMException` often surfaces only raw hex `HRESULT`s (`0x800Axxxx`, `0x80040Exx`, `0x800200xx`) unless `IErrorInfo` is explicitly read/freed and VB6 `FACILITY_CONTROL` (`0x800A0000`) / `FACILITY_ITF` (`0x80040200+`) error numbers are unpacked.
4. **One-way `ProgID -> CLSID` registration and `HKCR` shadowing:** `CurrentUserRegistryLeaseManager` previously registered `HKCU\Software\Classes\<ProgId>\CLSID` (for `CLSIDFromProgID`) without reverse `Software\Classes\CLSID\{clsid}\ProgID` / `VersionIndependentProgID` keys (needed by `ProgIDFromCLSID` in ADO, OLE DB enumerators, and VB6 `TypeName`), and without skipping `HKCU` writes when `Registry.ClassesRoot` already resolves the class on Desktop/Server Core.
5. **Repeated CoreCLR STA `OleMainThreadWndClass` pre-warming boilerplate:** Modern CoreCLR initializes `Thread.SetApartmentState(ApartmentState.STA)` lazily, deferring `RegisterOleWndClass` until the first built-in COM interop call or explicit `CoInitializeEx(0, COINIT_APARTMENTTHREADED)`. Raw native entry points (`DllGetClassObject`, `CoGetApartmentType`, or `msvbvm60.dll` window hooks) require native STA initialization up front.
6. **Win32 thread `LCID` decimal-separator corruption in VB6 / `oleaut32` Automation:** `oleaut32.dll` (`VarR8FromStr`, `VarBstrFromR8`, `VariantChangeType`, `IDispatch::Invoke`) and `msvbvm60.dll` (`CDbl`, `CStr`) use the Win32 kernel thread locale (`GetThreadLocale` / `SetThreadLocale`) rather than `.NET`'s `CultureInfo.CurrentCulture`, silently misparsing floating-point strings on comma-decimal Windows hosts.
7. **Unbalanced native `CoUninitialize` / `OleUninitialize` calls inside legacy COM DLLs:** Defective legacy COM binaries occasionally invoke an extra `CoUninitialize()` during teardown or error paths, prematurely tearing down the host STA worker's COM apartment unless that module's IAT slot is explicitly neutralized.
8. **Ambient CLSID in-proc server provenance probing without RCW side effects:** Verifying that `CoCreateInstance(CLSCTX_INPROC_SERVER)` resolves shared support coclasses (`msado15.dll`, `oledb32.dll`, `msjetoledb40.dll`, `msxml3.dll`) or worker coclasses from a private runtime directory rather than `System32` / `Common Files` without creating a GC-tracked managed RCW requires raw `IUnknown*` vtable probing and immediate `Marshal.Release`.
9. **Hand-rolled SxS `.manifest` XML string replacement and `<description>` PII sanitization for renamed worker DLLs:** Staging per-worker renamed COM DLLs (`Engine.dll` -> `Engine_00.dll`) or pruning unused companion `<file>` declarations requires structured XML rewriting, orphan `<comInterfaceExternalProxyStub>` cleanup, `<description>` PII stripping, and `ComManifestParser` invariant validation rather than fragile string replacements.

## Detailed technical plan

### COM-09 (P0): Explicit WinSxS bypass (`ComActivationOptions.ForceInProcessFallback`) & apartment-scoped fallback registration reference counting

#### Problem
- `Microsoft.Jet.OLEDB.4.0` and OLE DB service components fail under Desktop Win32 SxS (`CreateActCtxW`) when WinSxS `HKCR\CLSID` redirection hides `OLEDB_SERVICES = 0xfffffffe` from `oledb32.dll`, and Desktop SxS caches manifests sharing identical `<assemblyIdentity>` across worker directories.
- Multiple nested scopes on the same STA thread or concurrent MTA threads activating a shared support manifest must not prematurely `CoRevokeClassObject` while a sibling scope in the same apartment is still active, nor silently overwrite a conflicting `DllPath` bound to the same `CLSID`.

#### Design
1. Add `public bool ForceInProcessFallback { get; init; }` (default `false`) to `ComActivationOptions`.
2. In `ActivationContextApi`:
   - When `options.ForceInProcessFallback` is `true`, validate `NanoServerOptions.EnableSxsFallback` (failing closed with `InvalidOperationException` if `EnableSxsFallback == false`) and route directly to `CreateFallbackContext` without calling `CreateActCtxW`, setting `scope.IsUsingNanoServerFallback = true`.
   - Reference-count fallback `CoRegisterClassObject` leases per `(ApartmentKey, Clsid)` (keyed by native OS thread ID when the apartment is STA, and by a shared MTA apartment key under lock when the apartment is MTA):
     - Re-entering or overlapping the **same** `(ApartmentKey, Clsid, NormalizedDllPath)` increments the apartment lease count and reuses the active registration token; `CoRevokeClassObject` runs only when the apartment lease count drops to `0`.
     - Attempting to register a **different** `NormalizedDllPath` for an already-leased `(ApartmentKey, Clsid)` in the same apartment fails deterministically without clobbering the active registration.

#### Acceptance
- Integration tests on Desktop Windows (`x86` and `x64`, all 5 TFMs) verify that `ForceInProcessFallback = true` bypasses `CreateActCtxW`, sets `scope.IsUsingNanoServerFallback == true`, activates `NativeLifetimeProbe.dll` coclasses via `CoRegisterClassObject`, keeps registrations alive across nested STA scopes and overlapping concurrent MTA scopes until the final scope deactivates, rejects conflicting same-apartment `DllPath` registrations for the same `CLSID`, and unloads the worker DLL cleanly on final `Deactivate`.

### COM-10 (P0): Direct `HMODULE` class-factory instantiation (`ComClassFactory` & `IComActivationScope` helpers)

#### Problem
When concurrent workers load private copies of the same COM DLL (`worker-01\Server_01.dll`, `worker-02\Server_02.dll`) exposing identical CLSIDs, relying on process-wide `CoRegisterClassObject` (in MTA) or ambient `CoCreateInstance` creates cross-worker race windows or risks falling back to a globally registered `HKLM` DLL if an activation context is missing an entry.

#### Design
1. Add public static `ComClassFactory` utility (`CreateInstance`, `CreateInstance<TInterface>`, `CreateInstanceFromDll`, `CreateInstanceFromDll<TInterface>`) calling `GetProcAddress(moduleHandle, "DllGetClassObject")` -> `IClassFactory::CreateInstance` directly (with `IID_IUnknown` fallback) without touching SxS, `CoRegisterClassObject`, or `HKCR`.
2. Add `CreateInstance` and `CreateInstance<TInterface>` on `IComActivationScope` / `ComActivationScopeExtensions`, enforcing creating-thread affinity and `LoadedModuleHandles` bounds and automatically tracking returned RCWs via `scope.TrackObject(...)` when `trackObject == true`.

#### Acceptance
- Tests instantiate coclasses directly from `HMODULE` and DLL paths with zero manifests or registry keys, verify exact `HMODULE` ownership via `ComModuleDiagnostics.VerifyInstanceModule`, enforce scope thread affinity and bounds, and unload worker DLLs cleanly on `Deactivate`.

### COM-11 (P1): Rich COM `IErrorInfo` diagnostics & VB6 / `FACILITY_ITF` `HRESULT` unpacking (`ComErrorDiagnostics` & `ComErrorInfo`)

#### Problem
VB6 `Err.Raise`, Delphi `EOleSysError`, ATL `AtlReportError`, and ADO/Jet errors populate thread-local `oleaut32!SetErrorInfo` (`GUID`, `Source`, `Description`, `HelpFile`, `HelpContext`) and return `FACILITY_CONTROL` (`0x800A0000 | code`) or `FACILITY_ITF` (`0x80040200 + offset`) `HRESULT`s whose details are stripped or lost across raw vtable calls and inconsistent framework exception wrappers.

#### Design
1. Add immutable `ComErrorInfo` (`InterfaceId`, `Source`, `Description`, `HelpFile`, `HelpContext`, `ToSummaryString()`).
2. Add `ComErrorDiagnostics`:
   - `ConsumeCurrentErrorInfo()` and non-destructive `PeekCurrentErrorInfo()` reading `IErrorInfo` vtable slots `3`–`7` safely and freeing every `BSTR` in `finally`.
   - `CreateExceptionForHr(int hr, bool consumeErrorInfo = true)` returning an enriched `COMException` carrying `Data["ComErrorInfo"]`.
   - `TryGetVisualBasicErrorNumber(int hr, out int errorNumber)` and `TryGetInterfaceErrorOffset(int hr, out int offset)`.

#### Acceptance
- Native fixture export `PopulateProbeComErrorInfo` populates `ICreateErrorInfo` + `SetErrorInfo` and returns `0x800A03E9`; tests across `x86` and `x64` verify `PeekCurrentErrorInfo`, `ConsumeCurrentErrorInfo`, empty-slot `S_FALSE` behavior, `CreateExceptionForHr`, and `TryGetVisualBasicErrorNumber` / `TryGetInterfaceErrorOffset`.

### COM-12 (P1): Bidirectional `CLSID <-> ProgID` (`VersionIndependentProgID`) & `HKCR`-presence check in `CurrentUserRegistryLeaseManager`

#### Problem
Legacy ADO, OLE DB, and VB6 components call both forward `CLSIDFromProgID` (on versioned and version-independent ProgIDs) and reverse `ProgIDFromCLSID`, while workstations that already have matching `HKLM` (`HKCR`) registrations should not incur redundant `HKCU\Software\Classes` writes.

#### Design
1. Extend `ComManifestParser` to capture `versionIndependentProgId` attributes and secondary `<progid>` child elements, resolving `PrimaryProgId` and `VersionIndependentProgId`.
2. Add `public bool SkipCurrentUserRegistrationWhenPresentInClassesRoot { get; init; } = true;` to `ComActivationOptions`.
3. Extend `CurrentUserRegistryLeaseManager` to acquire reference-counted forward (`Software\Classes\<ProgId>\CLSID`) and reverse (`Software\Classes\CLSID\{clsid}\ProgID` and `VersionIndependentProgID`) leases, short-circuiting `HKCU` writes via a no-op lease when `Registry.ClassesRoot` already maps the expected value (and promoting to `HKCU` if a concurrent caller sets `SkipCurrentUserRegistrationWhenPresentInClassesRoot = false`).

#### Acceptance
- Tests verify both `CLSIDFromProgID` and `ProgIDFromCLSID` round-tripping across versioned and version-independent ProgIDs, `HKCR`-presence short-circuiting + promotion, and complete `HKCU` rollback on final release.

---

### COM-13 (P1): CoreCLR STA `OleMainThreadWndClass` pre-warming (`NanoServerOptions.EnsureCurrentStaThreadInitialized`)

#### Problem
CoreCLR initializes `Thread.SetApartmentState(ApartmentState.STA)` lazily, leaving raw native P/Invokes (`CoGetApartmentType`, `DllGetClassObject`, `msvbvm60.dll` window attachment) in `CO_E_NOTINITIALIZED` until the first managed COM interop operation or explicit `CoInitializeEx(0, COINIT_APARTMENTTHREADED)` call.

#### Design
1. Add idempotent `[ThreadStatic]`-guarded `NanoServerOptions.EnsureCurrentStaThreadInitialized()` that checks `CoGetApartmentType` on STA threads and performs a balanced `CoInitializeEx(0, COINIT_APARTMENTTHREADED)` / `CoUninitialize()` warm-up when `CO_E_NOTINITIALIZED` is observed.
2. Invoke `EnsureCurrentStaThreadInitialized()` automatically at the entry of `Executor.Activate`, `Executor.Execute`, and `Executor.Create` when running on `ApartmentState.STA` threads.

#### Acceptance
- Concurrency tests spawn 8 fresh `ApartmentState.STA` threads entering a barrier + contended lock + `Executor.Activate` simultaneously across `x86` and `x64` on all 5 TFMs and verify native `APTTYPE_STA` readiness from the first instruction.

### COM-14 (P1): Thread-affine Win32 Automation `LCID` & managed culture guard (`ComAutomationLocaleScope`)

#### Problem
`oleaut32.dll` (`VarR8FromStr`, `VarBstrFromR8`, `VariantChangeType`, `IDispatch::Invoke`) reads Win32 `GetThreadLocale()` rather than `CultureInfo.CurrentCulture` on modern `.NET`, while on `.NET Framework` assigning `CultureInfo.CurrentCulture` internally calls `SetThreadLocale(culture.LCID)` and overwrites a prior `SetThreadLocale(0x0409)` call when `InvariantCulture` (`0x007F`) is assigned afterward.

#### Design
Add sealed thread-affine `ComAutomationLocaleScope : IDisposable` (`Enter`, `EnterInvariant`, `InvariantLocaleId = 0x007F`, `UsEnglishLocaleId = 0x0409`, `UkEnglishLocaleId = 0x0809`) applying `CultureInfo.CurrentCulture` / `CurrentUICulture` **before** `kernel32!SetThreadLocale`, validating creating managed and Win32 thread identity on `Dispose()`, and restoring both managed cultures and Win32 `LCID` cleanly.

#### Acceptance
- Native exports `ParseDoubleWithThreadLocale` (`VarR8FromStr`) and `FormatDoubleWithThreadLocale` (`VarBstrFromR8`) verify failure on comma-decimal Polish (`0x0415`) outside the scope, exact `1234.56` parsing/formatting inside `ComAutomationLocaleScope.Enter()`, exact restoration of `0x0415` on `Dispose()`, and `InvalidOperationException` on cross-thread `Dispose()`.

### COM-15 (P2): Opt-in per-module unbalanced `CoUninitialize` / `OleUninitialize` W^X IAT guard (`ComModuleQuirks`)

#### Problem
Defective legacy third-party COM DLLs occasionally invoke an extra `CoUninitialize()` or `OleUninitialize()` while managed RCWs on the STA worker thread are still alive, tearing down a 1-refcount STA apartment prematurely.

#### Design
Add public static `ComModuleQuirks` (`SuppressUninitializeImports(IntPtr moduleHandle)`, `RestoreUninitializeImports(IntPtr moduleHandle)`) backed by `NanoServerOle2Shim`:
- Allocates a static-lifetime W^X native `ret` stub page (`PAGE_READWRITE` -> `FlushInstructionCache` -> `PAGE_EXECUTE_READ`).
- Patches standard and delay-load IAT slots for `CoUninitialize` and `OleUninitialize` **in that single non-system `HMODULE` only**, rejecting OS/COM/CLR modules (`combase.dll`, `ole32.dll`, `System32`/`SysWOW64`, CLR DLLs) with `InvalidOperationException` and cleaning up tracking state when the module unloads.

#### Acceptance
- Native exports `InvokeImportedCoUninitializeTwice` and `InvokeImportedOleUninitializeTwice` prove that an unpatched worker DLL tears down a 1-refcount STA apartment whereas `ComModuleQuirks.SuppressUninitializeImports` preserves both the STA apartment and live RCWs with strict W^X page protections across `x86` and `x64`.

### COM-16 (P2): CLSID in-proc server module provenance probe without RCW allocation (`ComModuleDiagnostics`)

#### Problem
`ComModuleDiagnostics.VerifyInstanceModule(object comObject, ...)` requires a managed RCW, which delays `DllCanUnloadNow() == S_OK` on `UnloadModulesOnDeactivate = true` scopes unless the caller forces `GC.Collect()`.

#### Design
Extend `ComModuleDiagnostics` with RCW-free `GetRegisteredInprocServerPath`, `InspectRegisteredInprocServer`, and `VerifyRegisteredInprocServer` overloads that invoke raw `CoCreateInstance(..., CLSCTX_INPROC_SERVER, IID_IUnknown, out IntPtr rawPtr)`, inspect the vtable slot directly, and call `Marshal.Release(rawPtr)` in `finally`.

#### Acceptance
- Tests across `x86` and `x64` on all 5 TFMs verify `Match` and `Mismatch` detection under both Desktop SxS and `ForceInProcessFallback = true`, followed by immediate `Deactivate` + `FreeLibrary` module unload with **zero** `GC.Collect()` calls.

---

### COM-17 (P1): Worker SxS manifest XML rewriter, `<file>` pruner & `<description>` sanitizer (`ComManifestRewriter`)

#### Problem
Multi-worker hosts staging renamed per-worker COM DLLs (`Server.dll` -> `Server_00.dll`) and pruning optional companion `<file>` tags need a validated, zero-dependency XML rewriter and `<description>` PII sanitizer.

#### Design
Add public sealed `ComManifestRewriter` (`FromFile`, `FromXml`, `WithAssemblyIdentityName`, `RenameFile`, `RenameFiles`, `RemoveFile`, `StripDescriptions`, `ToXmlString`, `ToUtf8Bytes`, `SaveIfChanged`) using in-box `System.Xml.Linq` (`DtdProcessing.Prohibit`, `XmlResolver = null`), validating output via `ComManifestParser` structural invariants (including rejecting manifests pruned to zero `<comClass>` and zero `<typelib>` entries), refusing source-file overwrites, and writing UTF-8 without BOM atomically via same-directory temp files only when bytes differ.

#### Acceptance
- Tests across `x86` and `x64` on all 5 TFMs rewrite `NativeLifetimeProbe` manifests to worker-renamed DLLs (`NativeLifetimeProbe_00.dll`), prune optional satellite `<file>` entries and orphan `<comInterfaceExternalProxyStub>` tags, strip `<description>` PII and XML comments, verify idempotent `SaveIfChanged` (`true` then `false`), reject unsafe filenames and in-place source overwrites, and activate the rewritten manifest cleanly under both Desktop `CreateActCtxW` and `ForceInProcessFallback = true`.
